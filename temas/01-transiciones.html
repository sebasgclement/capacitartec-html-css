Transiciones

La forma más simple de animar: suavizar el cambio entre dos estados de un mismo elemento, sin escribir un solo keyframe.

¿Qué problema resuelve?

Sin transition, todo cambio de estilo es instantáneo: un :hover que cambia el color pasa de un valor al otro en el mismo frame, de golpe. Se siente brusco y poco pulido.

transition le dice al navegador "cuando esta propiedad cambie de valor, no lo muestres de golpe: interpolá los valores intermedios durante este tiempo". No define un movimiento nuevo, solo suaviza uno que ya iba a pasar (por :hover, :focus, una clase que se agrega con JS, etc.).

Es la herramienta correcta para cambios de estado. Para loops, coreografías con varios pasos o algo que arranca solo sin que nada cambie, lo que hace falta es @keyframes (próximo tema).

Sintaxis mínima

.caja {
  transition: transform .35s ease, background-color .35s ease;
  /*           propiedad  duración timing, propiedad  duración timing */
}

.caja:hover {
  transform: translateY(-8px) scale(1.04);
  background-color: #334155;
}

El transition va en el estado de partida (la regla sin :hover), no en el estado final. Es el elemento en reposo el que sabe que, si algo cambia, tiene que transicionar — no importa hacia qué estado vaya.

Se pueden animar varias propiedades separadas por coma, cada una con su propia duración y curva:

transition-property: transform, background-color, border-radius;
transition-duration: .35s, .35s, .5s;
transition-timing-function: ease, ease, cubic-bezier(.2,.7,.2,1.1);

Errores comunes

  • Poner transition en :hover y no en el elemento base Si el transition solo está en .box:hover, la transición se aplica al entrar pero no al salir (o viceversa), porque al perder el hover el navegador vuelve a la regla base, que no tiene transición. Ponelo siempre en el estado de reposo.
  • Usar transition: all Funciona, pero anima cualquier propiedad que cambie, incluidas las que no esperás (por ejemplo si un script cambia width por otro motivo). Es más lento de calcular y más difícil de depurar. Mejor nombrar las propiedades.
  • Transicionar propiedades que disparan layout Animar width, height, top o left obliga al navegador a recalcular el layout en cada frame. transform y opacity se animan en la GPU, sin ese costo — casi siempre hay una forma de lograr el mismo efecto con transform.
  • Esperar que transition anime la aparición inicial Si un elemento nace con opacity: 1 directamente, transition no tiene "antes" y "después": no hay nada que interpolar. Para animar una entrada hace falta cambiar el valor después de que el elemento ya existe (con una clase, por ejemplo).

Cuándo NO usarlo

✔ Usá transition

Cambios de estado: hover, focus, una clase que se agrega/quita, abrir y cerrar un menú, un input que se resalta.

✘ Usá @keyframes

Loops infinitos, animaciones que arrancan solas sin que nada cambie de estado, o coreografías con más de dos pasos (0% → 50% → 100%).

Mini-ejercicio

Sobre el editor de arriba:

  1. Agregá box-shadow a la lista de transition de .box.
  2. En :hover, sumá una sombra más marcada.
  3. Probá transition-delay: .15s en una de las cajas y notá el pequeño respiro antes de que arranque.
Ver solución 
.box {
  transition: transform .35s ease, background-color .35s ease,
              border-radius .35s ease, box-shadow .35s ease;
}
.box:hover {
  transform: translateY(-8px) scale(1.04);
  background: #334155;
  border-radius: 24px;
  box-shadow: 0 12px 24px rgba(0,0,0,.4);
}

transition-delay no cambia la duración, solo cuándo arranca. Es útil para escalonar varias cajas: cada una con un delay un poco mayor que la anterior.
