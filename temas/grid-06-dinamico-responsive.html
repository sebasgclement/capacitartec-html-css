Grid dinámico y responsive

Una sola línea de CSS que arma una grilla responsive completa, sin una sola media query.

¿Qué problema resuelve?

Hasta acá, para que una galería tenga 4 columnas en escritorio, 2 en tablet y 1 en celular, había que escribir esto: 

.galeria { grid-template-columns: repeat(4, 1fr); }

@media (max-width: 900px) {
  .galeria { grid-template-columns: repeat(2, 1fr); }
}
@media (max-width: 500px) {
  .galeria { grid-template-columns: 1fr; }
}

Funciona, pero tiene dos problemas. Uno: elegiste 900px y 500px a ojo, y no coinciden con ningún dispositivo real. Dos: si mañana las tarjetas se hacen más anchas, hay que recalcular los tres breakpoints.

La combinación auto-fit + minmax() da vuelta el planteo: en vez de decir "cuántas columnas según el ancho de pantalla", decís "cuánto tiene que medir cada tarjeta como mínimo" y Grid calcula solo cuántas entran.

Sintaxis mínima

.galeria {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 16px;
}

Leído en voz alta: "repetí tantas columnas como entren, de mínimo 200px, y repartí el sobrante entre ellas".

Eso es todo. En 1200px entran 5 columnas; en 640px, 3; en 380px, 1. Sin media queries, sin breakpoints inventados, y funciona en anchos que ni probaste.

auto-fit vs auto-fill

Son casi iguales y la diferencia solo se nota cuando sobra espacio:

  • auto-fit: las columnas vacías se colapsan, y las que tienen contenido se estiran para ocupar todo.
  • auto-fill: las columnas vacías se mantienen reservadas, y los ítems conservan su ancho mínimo.

Con 3 tarjetas en una pantalla donde entrarían 6: con auto-fit las 3 se agrandan hasta llenar la fila; con auto-fill quedan chicas y con espacio vacío a la derecha. Para galerías, casi siempre querés auto-fit.

Errores comunes

  • Usar auto-fit con pocos elementos sin querer Con 2 tarjetas en una pantalla ancha, auto-fit las estira a media pantalla cada una. Si no querés eso, limitá el máximo: minmax(200px, 400px).
  • Un mínimo más grande que la pantalla minmax(400px, 1fr) se desborda en un celular de 360px. Si el mínimo no entra, se desborda igual. Para eso está min(400px, 100%) como mínimo.
  • Poner auto-fit adentro de minmax Es al revés: repeat(auto-fit, minmax(...)). El auto-fit es el primer argumento de repeat().
  • Combinar auto-fit con cantidades fijas repeat(auto-fit, ...) no se puede mezclar con otro repeat() de cantidad automática en la misma declaración.

Cuándo NO usarlo

✔ Usá auto-fit

Cuando todos los elementos son equivalentes y da igual cuántos entren por fila: galerías, tarjetas de producto, logos, un equipo de trabajo.

✘ Usá media queries

Cuando el layout tiene que cambiar de forma, no solo de cantidad: una barra lateral que en celular pasa a ir arriba.

Los dos enfoques conviven: auto-fit para el contenido repetido, media queries (o grid-template-areas, tema 9) para reorganizar la estructura general.

Mini-ejercicio

Una grilla de tarjetas de equipo:

  1. Cada tarjeta, mínimo 180px.
  2. Que nunca se desborde, ni en una pantalla de 320px.
  3. Sin escribir ni una media query.
Ver solución 
.equipo {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(180px, 100%), 1fr));
  gap: 16px;
}

El min(180px, 100%) es la parte que casi nunca se ve en los tutoriales, y es la que evita el desborde: significa "180px, salvo que el contenedor sea más chico, en cuyo caso ocupá el 100%".

Sin eso, en una pantalla de 320px con 16px de padding a cada lado, una columna de mínimo 180px entra justa... hasta que agregás el gap.
