Animaciones con scroll

Que un bloque aparezca con un fundido y un pequeño desplazamiento cuando entra en pantalla, en vez de estar visible desde el principio.

¿Qué problema resuelve?

transition y @keyframes animan algo que cambia de estado, pero ninguno de los dos sabe cuándo un elemento entra en el viewport al hacer scroll — eso no es un estado de CSS, es una posición en la pantalla.

La pieza que falta es IntersectionObserver, una API de JavaScript que avisa cuando un elemento entra o sale del área visible. El patrón es siempre el mismo: el elemento arranca invisible (opacity: 0) con una transición lista, el observer le agrega una clase (.in) cuando aparece en pantalla, y esa clase dispara la transición al estado visible.

JS decide cuándo, CSS decide cómo se ve el cambio. Ninguno de los dos hace todo el trabajo solo.

Sintaxis mínima

.card {
  opacity: 0;
  transform: translateY(24px);
  transition: opacity .6s ease, transform .6s ease;
}
.card.in { opacity: 1; transform: none; }
const obs = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) {
      entry.target.classList.add("in");
      obs.unobserve(entry.target); // ya cumplió su función, no hace más falta
    }
  });
}, { threshold: 0.1 });

document.querySelectorAll(".card").forEach((el) => obs.observe(el));

threshold: 0.1 significa "avisame cuando el 10% del elemento sea visible". rootMargin permite adelantar o atrasar ese momento respecto al borde real del viewport, por ejemplo "0px 0px -10% 0px" dispara un poco antes de llegar al fondo de la pantalla.

Errores comunes

  • No hacer unobserve después de animar Si no se deja de observar, el callback sigue disparando cada vez que el elemento entra y sale del viewport, y si la clase no se saca al salir, no pasa nada visible — pero es trabajo de más para el navegador, sin ningún beneficio.
  • El elemento nunca mide 0 al observarlo Si el elemento tiene display: none al momento de crear el observer, no tiene tamaño y el cálculo de intersección puede comportarse de forma rara. El patrón de "empieza invisible" tiene que ser con opacity: 0, no con display: none.
  • Animar demasiados elementos a la vez Observar 50 tarjetas individuales con la misma configuración funciona, pero si todas entran juntas (por ejemplo una grilla completa), suelen verse mejor con un pequeño delay escalonado entre una y la siguiente que si todas aparecen exactamente en el mismo frame.
  • Olvidarse de que existe una alternativa 100% CSS Los navegadores modernos ya soportan animation-timeline: view(), que logra un efecto parecido sin una sola línea de JavaScript. Es el tema que sigue.

Cuándo NO usarlo

✔ IntersectionObserver

Cuando necesitás lógica además de animar: cargar una imagen recién cuando aparece (lazy loading), contar una vista, o disparar algo en JavaScript además del efecto visual.

✘ animation-timeline (CSS)

Si lo único que hace falta es el efecto visual de aparición, sin ninguna lógica adicional — ahí conviene la versión sin JavaScript del próximo tema.
