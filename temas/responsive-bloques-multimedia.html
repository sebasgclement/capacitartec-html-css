Bloques y multimedia flexible

La base de todo lo demás: que imágenes, videos e iframes se achiquen junto con la pantalla en vez de desbordarla.

¿Qué problema resuelve?

Una imagen tiene un ancho intrínseco (el de su archivo original, por ejemplo 1600px). Si no le decís nada, ese ancho es fijo: en un celular de 360px de pantalla, la imagen se corta y aparece una barra de scroll horizontal — uno de los errores más comunes en sitios que "casi" son responsive.

Los videos e iframes (mapas, YouTube) tienen el problema inverso: muchas veces se insertan con width y height fijos en píxeles, así que en pantallas chicas no se achican, y en pantallas grandes se quedan pequeños en vez de aprovechar el espacio.

La solución para imágenes es una sola línea de CSS. Para video/iframe hace falta un truco distinto, porque no se puede poner height: auto en un iframe sin perder la proporción.

Sintaxis mínima

Imágenes fluidas:

img {
  max-width: 100%;   /* nunca más ancha que su contenedor */
  height: auto;      /* mantiene la proporción al achicarse */
  display: block;
}

Video/iframe con proporción fija (16:9, por ejemplo):

.contenedor-video {
  width: 100%;
  aspect-ratio: 16 / 9;
}
.contenedor-video iframe,
.contenedor-video video {
  width: 100%;
  height: 100%;
}

aspect-ratio le dice al navegador "reservá este alto en relación al ancho, antes de saber el tamaño real del contenido" — el mismo mecanismo evita que la página "salte" cuando el video termina de cargar.

Errores comunes

  • Poner max-width: 100% sin height: auto Sin height: auto, si la imagen tiene un height fijo en algún otro selector, se aplasta o se estira: el ancho se achica pero el alto no acompaña, y la imagen se ve distorsionada.
  • Usar width: 100% en vez de max-width: 100% width: 100% fuerza a la imagen a ocupar todo el contenedor incluso si es más chica que él, agrandándola y pixelándola. max-width: 100% solo actúa como límite.
  • Iframes con width y height en atributos HTML fijos Los atributos width="560" height="315" de un embed de YouTube son solo el tamaño por defecto. Sin el truco de aspect-ratio (o el position: absolute más viejo), esos valores fijos ganan y el video no se adapta.
  • No reservar espacio para imágenes que tardan en cargar Si la imagen no tiene aspect-ratio (o atributos width/height que el navegador usa para inferirlo), el layout "salta" cuando termina de cargar y empuja el contenido de abajo. Esto se llama layout shift.

Cuándo NO usarlo

✔ max-width: 100%

Prácticamente siempre, para cualquier imagen de contenido: fotos, ilustraciones, capturas de pantalla.

✘ Excepción: íconos e imágenes de UI

Un ícono de 24px o el logo de la barra de navegación normalmente querés que tenga un tamaño fijo, no que se achique con el contenedor. Ahí no aplica esta regla.

Mini-ejercicio

Sobre el editor de arriba:

  1. Agregá una segunda imagen dentro de la misma tarjeta.
  2. Ponelas en una fila con display: flex; gap: 12px; en el contenedor.
  3. Verificá que ninguna de las dos se desborde de su mitad de la fila.
Ver solución 
.card { display: flex; gap: 12px; }
.foto {
  max-width: 100%;
  flex: 1 1 0;   /* cada imagen se reparte el espacio disponible por igual */
  height: auto;
}

flex: 1 1 0 hace que las dos imágenes compartan el ancho disponible en partes iguales, y max-width: 100% sigue evitando que cualquiera de las dos se desborde de su porción.
