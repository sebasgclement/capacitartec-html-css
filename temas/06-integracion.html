Integración en proyectos

Todo lo anterior junto en una página real, y las dos reglas de buen gusto que separan una animación prolija de una que cansa.

¿Qué problema resuelve?

Cada tema anterior mostró una técnica aislada. En un proyecto real conviven varias a la vez: hover en botones, reveal al hacer scroll, quizás un typewriter en el hero. El desafío ya no es "cómo se hace esto", sino cuándo conviene cada una y cómo no terminar con una página que se mueve todo el tiempo.

Ahí entran dos reglas que separan un sitio con buen gusto de uno cansador: respetar prefers-reduced-motion (para quien configuró su sistema para minimizar el movimiento) y animar solo transform y opacity cuando se pueda, que son las dos propiedades que el navegador puede animar sin recalcular el layout.

Sintaxis mínima

El patrón de "reveal" reutilizable que vas a escribir una y otra vez:

.reveal {
  opacity: 0;
  transform: translateY(16px);
  transition: opacity .5s ease, transform .5s ease;
}
.reveal.in { opacity: 1; transform: none; }

Y la regla que nunca debería faltar en un proyecto con animaciones:

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}

Esa media query detecta si la persona activó "reducir movimiento" en la configuración de su sistema operativo, y en ese caso corta prácticamente todas las duraciones a casi cero — el cambio de estado sigue pasando, pero sin la animación de por medio.

Errores comunes

  • Animar todo lo que se pueda, "porque se puede" Cada elemento con hover, cada tarjeta con su propio reveal, un typewriter en cada título... Demasiado movimiento a la vez compite por la atención y cansa. Reservá el efecto más llamativo para lo que realmente importa.
  • No respetar prefers-reduced-motion Para algunas personas, el movimiento excesivo no es solo una molestia estética: puede causar mareo o dificultar la lectura. La media query es una sola regla de CSS; no hay excusa para omitirla en un proyecto real.
  • Reveals que tapan contenido importante Si el transform: translateY() inicial es muy grande, el contenido puede arrancar fuera del área visible y el usuario nota un salto raro al aparecer. Con 16-24px alcanza para que se note el movimiento sin exagerar.
  • Combinar demasiadas técnicas sin necesidad No todo proyecto necesita scroll-driven animations, typewriter y WAAPI a la vez. Elegí la herramienta más simple que resuelve el efecto que necesitás — es más fácil de mantener.

Cuándo NO usarlo

✔ Animar

Feedback de interacción (hover, focus, click), y para guiar la atención hacia algo importante que acaba de aparecer.

✘ No animar

Contenido que se lee de forma continua (texto largo, tablas de datos), o cuando prefers-reduced-motion está activo: ahí la animación se corta, no se reemplaza por otra cosa.
