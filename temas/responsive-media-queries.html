Media Queries

La herramienta central del responsive design: aplicar CSS distinto según el tamaño de pantalla, o según las preferencias del sistema de quien te visita.

¿Qué problema resuelve?

Un layout de 3 columnas se ve perfecto en un monitor, pero en un celular esas columnas quedan de 100px de ancho, ilegibles. El CSS normal no tiene forma de decir "esta regla solo aplica si la pantalla mide tanto" — para eso están las media queries.

Además de tamaño de pantalla, las media queries también leen preferencias del sistema operativo: si la persona activó modo oscuro, o si pidió reducir las animaciones. Es "responsive" en un sentido más amplio que solo el ancho de pantalla.

Sintaxis mínima

.grid { grid-template-columns: 1fr; }

@media (min-width: 600px) {
  .grid { grid-template-columns: repeat(2, 1fr); }
}
@media (min-width: 900px) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}

min-width se lee "a partir de este ancho" — es la base del enfoque mobile first (próximo tema): se empieza con el estilo para pantallas chicas, y cada media query agrega mejoras a medida que hay más espacio.

Preferencias del sistema, sin ningún ancho de por medio:

@media (prefers-color-scheme: dark) { /* la persona usa modo oscuro */ }
@media (prefers-reduced-motion: reduce) { /* pidió menos movimiento */ }

Errores comunes

  • Mezclar min-width y max-width para el mismo breakpoint Usar las dos estrategias a la vez (algunas reglas "a partir de" y otras "hasta") en el mismo proyecto genera reglas que se pisan y breakpoints difíciles de rastrear. Elegí una — normalmente min-width (mobile first) — y sostenela.
  • Breakpoints "mágicos" sin relación con el contenido 320px, 768px, 1024px son números de dispositivos específicos que cambian todo el tiempo. Es mejor elegir el breakpoint en el punto exacto donde tu diseño empieza a verse mal, sea cual sea ese número.
  • No probar los estados intermedios Un layout puede verse bien a 400px y a 1200px, pero raro a 700px. Conviene arrastrar el borde de la ventana (o el modo responsive del navegador) en vez de solo mirar 2-3 anchos fijos.
  • Ignorar prefers-reduced-motion Es una media query, no una propiedad exótica — se usa exactamente igual que las de ancho. No incluirla en un proyecto con animaciones es un descuido de accesibilidad fácil de evitar.

Cuándo NO usarlo

✔ Media queries

Cuando el layout general de la página tiene que cambiar según el ancho de la ventana o las preferencias del sistema.

✘ Container queries

Cuando lo que tiene que reaccionar es un componente reutilizable (una tarjeta, un widget) según el espacio que le toca en su contenedor, no el de toda la pantalla. Es el último tema del módulo.

Mini-ejercicio

Sobre el editor de arriba:

  1. Agregá una media query (min-width: 1100px) que pase la grilla a 4 columnas.
  2. Sumá @media (prefers-reduced-motion: reduce) que anule cualquier transition que agregues a .box:hover.
Ver solución 
@media (min-width: 1100px) {
  .grid { grid-template-columns: repeat(4, 1fr); }
}

.box { transition: transform .2s ease; }
.box:hover { transform: translateY(-4px); }

@media (prefers-reduced-motion: reduce) {
  .box { transition: none; }
}
