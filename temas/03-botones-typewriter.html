Botones animados y Typewriter

Dos efectos clásicos hechos con las herramientas que ya conocés: pseudo-elementos + transition para el botón, y steps() para el texto que se escribe solo.

¿Qué problema resuelve?

Un botón que reacciona al hover se siente vivo; uno que no cambia nunca se siente "muerto", aunque funcione igual. La mayoría de estos efectos no necesitan JavaScript ni imágenes: se resuelven con ::before/::after y transition, que ya viste antes.

El efecto typewriter (texto que aparece letra por letra) parece necesitar JavaScript, pero CSS tiene una solución elegante para el caso simple: animar el width de un texto con white-space: nowrap y overflow: hidden, con una función de tiempo especial llamada steps() que avanza en saltos discretos en vez de suave.

Sintaxis mínima

Glow con pseudo-elemento:

.btn { position: relative; overflow: hidden; }
.btn::before {
  content: "";
  position: absolute; inset: -2px;
  background: conic-gradient(from 180deg, #22d3ee, #f472b6, #22d3ee);
  filter: blur(12px);
  opacity: 0;
  transition: opacity .25s;
}
.btn:hover::before { opacity: .6; }

Typewriter con steps():

.type {
  width: 0;
  white-space: nowrap;
  overflow: hidden;
  border-right: 2px solid;
  animation: typing 3s steps(30, end) 1 both,
              blink .8s step-end infinite;
}
@keyframes typing { from { width: 0; } to { width: 100%; } }
@keyframes blink  { 50% { border-color: transparent; } }

steps(30, end) divide la animación en 30 saltos iguales en vez de un movimiento continuo — por eso el texto "escribe" letra por letra y no se desliza. El número de pasos debería ser cercano a la cantidad de caracteres del texto para que se vea prolijo.

Errores comunes

  • Olvidar position: relative en el botón El ::before se posiciona con absolute respecto al ancestro posicionado más cercano. Sin position: relative en .btn, el glow se va a posicionar respecto a otro elemento (o al body) y termina en cualquier lado.
  • Olvidar z-index en el contenido del botón Si el ::before queda por encima del texto/ícono del botón, hay que subir el contenido con position: relative; z-index: 1;, como en el ejemplo.
  • Typewriter sin white-space: nowrap Sin eso, el texto puede saltar de línea a mitad de la animación de width, y el efecto se ve roto en vez de "escribiéndose".
  • Un texto typewriter muy largo con pocos steps Con pocos steps() para un texto largo, cada salto revela varias letras de golpe: se ve entrecortado en vez de fluido.

Cuándo NO usarlo

✔ Typewriter en CSS puro

Un texto fijo que se escribe una sola vez al cargar la página (un título, un hero). Cero JavaScript, funciona siempre.

✘ Typewriter en JS

Si el texto cambia dinámicamente, hay varias frases en secuencia, o necesitás que también borre letra por letra — ahí sí hace falta JavaScript, como en la segunda demo del archivo original.

.btn-underline {
  position: relative;
  display: inline-block;
  padding: 10px 2px;
  color: #e5e7eb;
  text-decoration: none;
}
.btn-underline::after {
  content: "";
  position: absolute;
  left: 0; right: 100%; bottom: 0;
  height: 2px;
  background: linear-gradient(90deg, #22d3ee, #f472b6);
  transition: right .35s ease;
}
.btn-underline:hover::after { right: 0; }

El truco es animar right de 100% a 0: la línea "crece" desde la izquierda porque el borde derecho del ::after se va acercando al borde derecho del link.
