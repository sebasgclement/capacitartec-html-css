Grid areas

Dibujar el layout con nombres en vez de contar líneas. Probablemente la función más linda de todo CSS.

¿Qué problema resuelve?

Con lo del tema 7, un layout clásico de página se escribe así: 

.header  { grid-column: 1 / 3; grid-row: 1 / 2; }
.sidebar { grid-column: 1 / 2; grid-row: 2 / 3; }
.main    { grid-column: 2 / 3; grid-row: 2 / 3; }
.footer  { grid-column: 1 / 3; grid-row: 3 / 4; }

Funciona perfecto. El problema es que no se entiende de un vistazo: hay que leer ocho números y armar el dibujo en la cabeza. Y si tenés que mover la sidebar a la derecha, hay que recalcular casi todo.

grid-template-areas te deja dibujar el layout con texto, literalmente. El CSS pasa a tener la forma del resultado.

Sintaxis mínima

.pagina {
  display: grid;
  grid-template-columns: 200px 1fr;
  grid-template-rows: auto 1fr auto;

  grid-template-areas:
    "header  header"
    "sidebar main"
    "footer  footer";
}

/* Y en cada hijo, el nombre del área que ocupa */
.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main    { grid-area: main; }
.footer  { grid-area: footer; }

Cada string entre comillas es una fila. Cada palabra dentro es una columna. Repetir un nombre en celdas contiguas hace que el área se extienda para cubrirlas.

Un punto . deja la celda vacía: 

grid-template-areas:
  "header header"
  "sidebar main"
  ".      footer";   /* la celda de abajo a la izquierda queda vacía */

Resultado

Cambiá "sidebar main" por "main sidebar": moviste la barra lateral al otro lado sin tocar el HTML y sin recalcular una sola línea.

Errores comunes

  • Filas con distinta cantidad de columnas Todas las strings tienen que tener la misma cantidad de nombres. Si una fila tiene 2 y otra 3, la propiedad entera se ignora y el layout se desarma sin aviso.
  • Áreas en forma de L o de T Un área tiene que ser siempre un rectángulo. Repetir el mismo nombre en celdas que no forman rectángulo invalida la declaración.
  • Poner comillas alrededor del nombre en grid-area En el contenedor van entre comillas; en el hijo no: grid-area: header, sin comillas.
  • Olvidarse de nombrar un hijo Si un hijo no tiene grid-area, no queda afuera: se acomoda automáticamente y suele aparecer en un lugar inesperado, creando filas implícitas.
  • Poner coma entre las filas Van una debajo de otra, separadas solo por el salto de línea. Sin comas.

Cuándo NO usarlo

✔ Usá areas

Cuando las piezas tienen identidad propia y son pocas: el esqueleto de una página, una ficha de producto, un formulario con zonas.

✘ Usá líneas o automático

Cuando hay muchos elementos iguales o la cantidad es dinámica. Nadie va a nombrar 30 tarjetas de una galería.

Donde más brilla es en responsive: redibujás el mismo layout dentro de una media query y listo, sin tocar ninguna otra regla. 

@media (max-width: 600px) {
  .pagina {
    grid-template-columns: 1fr;
    grid-template-areas:
      "header"
      "main"
      "sidebar"
      "footer";
  }
}

Fijate que ahí además cambiaste el orden: en celular el contenido principal va antes que la barra lateral, aunque en el HTML esté después.

Mini-ejercicio

Dibujá el layout de un panel de control:

  1. Una barra superior de ancho completo.
  2. Un menú lateral izquierdo que llegue hasta abajo.
  3. Un área de gráficos arriba a la derecha y una tabla debajo.
Ver solución 
.panel {
  display: grid;
  grid-template-columns: 200px 1fr;
  grid-template-rows: 60px 1fr 1fr;
  grid-template-areas:
    "barra  barra"
    "menu   graficos"
    "menu   tabla";
  gap: 12px;
  min-height: 100vh;
}

.barra    { grid-area: barra; }
.menu     { grid-area: menu; }
.graficos { grid-area: graficos; }
.tabla    { grid-area: tabla; }

El menú aparece dos veces en la misma columna y eso lo estira a lo alto de las dos filas: sigue siendo un rectángulo, así que es válido.
