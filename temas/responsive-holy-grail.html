Ejercicio "Holy Grail"

El layout más clásico de la web (header, nav, contenido, aside y footer) armado para que se reordene solo en pantallas chicas.

¿Qué problema resuelve?

Se llama "Holy Grail" (santo grial) porque durante años fue sorprendentemente difícil de lograr bien con las herramientas viejas de CSS: 3 columnas donde la del medio ocupa el espacio flexible, con header y footer de ancho completo arriba y abajo.

Con Grid (que ya viste) el layout de escritorio es simple. Lo que hace responsive a este ejercicio es la parte que falta en la mayoría de los tutoriales: qué pasa con esas 3 columnas en un celular, donde simplemente no entran una al lado de la otra. La respuesta es grid-template-areas distinto dentro de una media query — el mismo layout, reordenado.

Sintaxis mínima

.layout {
  display: grid;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header"
    "main"
    "footer";
}

@media (min-width: 900px) {
  .layout {
    grid-template-columns: 200px 1fr 220px;
    grid-template-areas:
      "header header header"
      "nav    main   aside"
      "footer footer footer";
  }
}

nav    { grid-area: nav; }
main   { grid-area: main; }
aside  { grid-area: aside; }
header { grid-area: header; }
footer { grid-area: footer; }

La base (sin media query) es mobile-first: todo apilado en una sola columna. A partir de 900px, se redibuja el mismo grid-template-areas con 3 columnas — exactamente la técnica que viste en la ficha de "Creando una página web" de Grid, ahora explícitamente pensada mobile-first.

Errores comunes

  • Repetir grid-template-columns sin repetir grid-template-areas Cambiar solo las columnas dentro de la media query no alcanza si el mapa de áreas de la base tiene una cantidad distinta de celdas — las dos declaraciones tienen que ser consistentes entre sí en cada breakpoint.
  • Elegir el breakpoint por el dispositivo en vez del contenido 900px no es un número mágico: es donde el nav y el aside dejan de caber cómodos al lado del contenido principal. Ajustá el breakpoint a tu contenido real, como viste en el tema de Media Queries.
  • Olvidar min-height en el layout completo Sin darle una altura mínima al contenedor general (por ejemplo 100vh), en una página con poco contenido el footer no queda pegado abajo — el mismo problema que viste en el laboratorio de CSS Grid.
  • Un orden de tabulación que no coincide con el visual Reordenar visualmente con grid-template-areas no cambia el orden del HTML. Si en móvil el nav queda arriba del main mientras que en el HTML está después, alguien navegando con teclado en desktop pasa primero por el contenido y recién después por la navegación — revisá que el orden del documento tenga sentido en los dos casos.

Cuándo NO usarlo

✔ Este patrón

El esqueleto de una página de contenido clásica: blogs, sitios institucionales, dashboards con navegación lateral.

✘ Layouts sin navegación lateral

Landing pages de una sola columna, o apps donde todo el contenido es central sin sidebar — ahí el "Holy Grail" completo es más estructura de la que hace falta.

Mini-ejercicio

Sobre el editor de arriba:

  1. Agregá un breakpoint intermedio (por ejemplo 380px) donde el nav pase a mostrarse como una fila horizontal de links, en vez de una lista vertical, aunque el layout general siga apilado.
  2. Achicá el aside a 130px de ancho en la versión de escritorio.
Ver solución 
@media (min-width: 380px) {
  nav ul { display: flex; gap: 12px; padding-left: 0; list-style: none; }
}

@media (min-width: 560px) {
  .layout { grid-template-columns: 140px 1fr 130px; }
}

Fijate que agregaste un breakpoint que no coincide con el que ya existía (560px): las media queries no tienen que ser todas iguales, cada elemento puede tener el punto de quiebre que le sirva.
