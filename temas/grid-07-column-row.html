Grid column y row

Hasta ahora los elementos se acomodaban solos. Acá empezás a decidir exactamente qué celdas ocupa cada uno.

¿Qué problema resuelve?

El acomodo automático está bien para contenido parejo, pero casi ningún diseño real es parejo: en un blog el artículo destacado ocupa el ancho completo, en un dashboard el gráfico principal es el doble de grande, en una galería una foto va apaisada.

grid-column y grid-row se aplican al ítem (no al contenedor, como todo lo anterior) y le dicen entre qué líneas tiene que ir.

Acá se vuelve importante lo que vimos en el tema 2: las líneas se numeran desde 1, y con 3 columnas hay 4 líneas verticales. 

1        2        3        4     ← líneas
 |  col1  |  col2  |  col3  |

Sintaxis mínima

/* Desde la línea 1 hasta la 3: ocupa 2 columnas */
.destacado { grid-column: 1 / 3; }

/* Lo mismo, pero diciendo cuántas pistas ocupar */
.destacado { grid-column: 1 / span 2; }

/* Sin importar dónde empiece: ocupá 2 columnas */
.destacado { grid-column: span 2; }

/* -1 es la última línea: de punta a punta */
.ancho-total { grid-column: 1 / -1; }

/* Filas: exactamente igual */
.alto { grid-row: 2 / 4; }

/* Atajo de los dos juntos: fila-inicio / col-inicio / fila-fin / col-fin */
.pieza { grid-area: 1 / 1 / 3 / 3; }

grid-column: 1 / -1 es el más útil de todos: significa "de la primera a la última línea" sin importar cuántas columnas tenga la grilla. Si mañana pasás de 3 a 5 columnas, sigue funcionando.

Errores comunes

  • Confundir número de línea con número de columna grid-column: 1 / 2 ocupa una sola columna, no dos. Las líneas son los bordes, no las pistas. Si querés dos columnas, es 1 / 3.
  • Aplicarlo al contenedor grid-column va en el hijo. Es la primera propiedad de Grid que cambia de lugar, y confunde a todo el mundo.
  • Que -1 no llegue hasta el final -1 es la última línea del grid explícito. Si las columnas se generaron implícitamente, -1 no cuenta esas y el resultado no es el esperado.
  • Posicionar en una línea que no existe grid-column: 1 / 6 en una grilla de 3 columnas hace que Grid cree columnas implícitas para llegar. Suele verse como un desborde inexplicable hacia la derecha.
  • Dejar huecos sin darse cuenta Al posicionar un elemento a mano, los que vienen después siguen acomodándose automáticamente y pueden saltear celdas. El tema 8 (dense) es justo sobre eso.

Cuándo NO usarlo

✔ Posicioná a mano

Cuando hay piezas especiales: un destacado, un banner de ancho completo, una celda que ocupa dos filas.

✘ Dejá el automático

Cuando todos los elementos son iguales. Posicionar 20 tarjetas a mano es trabajo perdido y se rompe apenas cambia la cantidad.

Y si el layout completo está armado de piezas con nombre propio (header, sidebar, main, footer), lo que vas a querer es grid-template-areas, que se lee muchísimo mejor que contar líneas. Es el tema 9.

Mini-ejercicio

Sobre una grilla de 3 columnas, armá la portada de un blog:

  1. El artículo destacado ocupa las 3 columnas de la primera fila.
  2. Debajo, 3 artículos normales de una columna cada uno.
  3. Al final, un bloque de newsletter que ocupe las 2 primeras columnas.
Ver solución 
.blog {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

.destacado  { grid-column: 1 / -1; }
.newsletter { grid-column: 1 / 3; }
/* los 3 artículos normales no llevan nada:
   se acomodan solos en las celdas libres */

Fijate que solo escribiste dos reglas. Esa es la idea: posicionás las excepciones y dejás que Grid resuelva el resto.

Usar 1 / -1 en el destacado y no 1 / 4 hace que siga funcionando si mañana la grilla pasa a tener 4 columnas.
