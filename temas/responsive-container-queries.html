Container Queries

El cierre lógico del módulo: hacer que un componente reaccione al espacio real que tiene disponible, no al tamaño de toda la pantalla.

¿Qué problema resuelve?

Una media query pregunta por el ancho del viewport (la ventana del navegador). El problema: una misma tarjeta de producto puede aparecer en una barra lateral angosta y, en otra página, ocupar el ancho completo — el viewport es el mismo en los dos casos, pero el espacio real disponible para la tarjeta es totalmente distinto.

Las container queries resuelven exactamente eso: en vez de preguntar por el ancho de toda la pantalla, preguntan por el ancho de su propio contenedor. La misma tarjeta se adapta sola según dónde la pongas, sin necesitar una clase distinta para cada contexto.

Sintaxis mínima

/* 1. Declarás que un elemento es un "contenedor" a observar */
.tarjeta-wrap {
  container-type: inline-size;
  container-name: tarjeta;   /* opcional, para ser específico */
}

/* 2. Los hijos reaccionan al ancho de ESE contenedor */
@container tarjeta (min-width: 420px) {
  .tarjeta { display: grid; grid-template-columns: 80px 1fr; }
}

container-type: inline-size; es el paso que casi siempre se olvida: sin declarar un contenedor en algún ancestro, @container no tiene de qué ancho hablar y la regla no hace nada.

También existen unidades relativas al contenedor, como cqw (1% del ancho del contenedor), paralelas a vw pero para este nuevo caso.

Errores comunes

  • Olvidar container-type en el ancestro Es el error más común: escribís @container (min-width: ...) pero ningún elemento por encima declaró container-type: inline-size. La regla se ignora sin ningún aviso.
  • Poner container-type en el mismo elemento que tiene el @container El contenedor y el elemento que reacciona no pueden ser el mismo: el contenedor mide a sus hijos. Por eso en el ejemplo hay un .tarjeta-wrap (contenedor) envolviendo a .tarjeta (el que reacciona).
  • Confundir con media queries @container nunca mide el viewport, solo el contenedor más cercano con container-type declarado. Si necesitás reaccionar al tamaño de toda la ventana, es @media, no esto.
  • container-name mal escrito o repetido en contenedores anidados Sin container-name, @container usa el contenedor más cercano. Si hay contenedores anidados y necesitás apuntar a uno específico que no es el más cercano, ahí sí hace falta nombrarlo.

Cuándo NO usarlo

✔ Container queries

Componentes reutilizables que van a vivir en contextos distintos: tarjetas, widgets de sidebar, elementos de un design system.

✘ Media queries

Decisiones de layout a nivel de página completa: si el sitio entero pasa de una columna a tres, eso sigue siendo el ancho del viewport, no de un contenedor puntual.

Mini-ejercicio

Sobre el editor de arriba:

  1. Agregá una tercera tarjeta con un ancho intermedio (por ejemplo 320px).
  2. Sumá un segundo @container (min-width: 500px) que además agrande la fuente del .titulo.
  3. Nombrá el contenedor con container-name: tarjeta; y actualizá el @container para usar ese nombre.
Ver solución 
.tarjeta-wrap {
  container-type: inline-size;
  container-name: tarjeta;
}

@container tarjeta (min-width: 380px) { /* ... */ }
@container tarjeta (min-width: 500px) {
  .titulo { font-size: 1.2rem; }
}

Nombrar el contenedor no cambia el comportamiento acá (solo hay un nivel), pero es buena práctica en proyectos reales donde puede haber contenedores anidados y necesitás ser explícito sobre a cuál te referís.
