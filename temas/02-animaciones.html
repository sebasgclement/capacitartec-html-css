Animaciones con @keyframes

Cuando una transición de dos puntos no alcanza: coreografías con varios pasos, loops infinitos, y control fino de cada etapa.

¿Qué problema resuelve?

transition solo sabe interpolar entre dos estados: el de antes y el de después. No hay forma de decirle "primero subí, después girá, y recién ahí volvé a bajar" — eso son 3 pasos, no 2.

@keyframes define una secuencia con nombre, con tantos puntos intermedios (0%, 50%, 100%, o los que necesites) como haga falta. Y a diferencia de transition, no necesita que nada cambie de estado primero: puede arrancar solo, apenas el elemento existe, y repetirse para siempre.

Sintaxis mínima

@keyframes bounce {
  0%, 100% { transform: translateY(0); }
  50%      { transform: translateY(-40px); }
}

.pelota {
  animation: bounce 1s ease-in-out infinite;
  /*          nombre  duración timing   repetición */
}

Primero se declara la secuencia con @keyframes <nombre>, con los porcentajes que quieras (podés usar from/to como sinónimos de 0%/100%). Después, cualquier elemento la usa con animation-name (o el shorthand animation).

Las propiedades sueltas, si no querés el shorthand:

animation-name: bounce;
animation-duration: 1s;
animation-timing-function: ease-in-out;
animation-iteration-count: infinite;   /* un número, o infinite */
animation-direction: alternate;        /* normal | reverse | alternate */
animation-fill-mode: both;             /* qué valor conserva antes/después */
animation-play-state: running;         /* running | paused */

Errores comunes

  • Usar el nombre de un keyframe que no existe (o con un typo) CSS no avisa: la animación simplemente no hace nada, sin error en consola. Si algo no se mueve, lo primero es revisar que animation-name coincida exactamente con el @keyframes.
  • Olvidar animation-iteration-count: infinite Por defecto una animación corre una sola vez y vuelve al estado original (a menos que uses fill-mode). Si esperabas un loop y solo ves un pantallazo, es esto.
  • Confundir fill-mode Sin fill-mode, apenas termina la animación el elemento vuelve a su estilo original, no se queda en el último frame. forwards conserva el estado final; backwards aplica el primer frame incluso antes de arrancar (útil con delay).
  • Animar con loops en contenido que se lee Un elemento que titila o rebota permanentemente al lado de texto distrae y puede resultar molesto para quien navega. Reservá los loops infinitos para elementos decorativos, y respetá prefers-reduced-motion (lo vas a ver en el tema de integración).

Cuándo NO usarlo

✔ Usá @keyframes

Loops (un spinner de carga), coreografías de varios pasos, o cualquier animación que tiene que arrancar sola sin depender de un cambio de estado.

✘ Usá transition

Un cambio simple de A a B disparado por hover, focus o una clase. Escribir un @keyframes de dos puntos para eso es más código para el mismo resultado.

Mini-ejercicio

Sobre el editor de arriba:

  1. Creá un @keyframes spin que rote de 0deg a 360deg.
  2. Aplicalo a una tercera tarjeta con animation: spin 2s linear infinite.
  3. Pausá esa animación al pasar el mouse, con :hover { animation-play-state: paused; }.
Ver solución 
@keyframes spin {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}

.spin .ball {
  animation: spin 2s linear infinite;
}
.spin:hover .ball {
  animation-play-state: paused;
}

animation-play-state es la forma declarativa de pausar sin JavaScript: el navegador congela la animación en el frame exacto donde estaba.
