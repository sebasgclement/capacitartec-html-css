Subgrid

Cómo hacer que los elementos de adentro de una tarjeta se alineen con los de las tarjetas vecinas. El problema que Grid tardó años en resolver.

¿Qué problema resuelve?

Imaginate tres tarjetas de producto, cada una con título, descripción y precio. Los títulos tienen largos distintos: uno ocupa una línea, otro dos.

Resultado: los precios quedan a distinta altura. Se ve descuidado, y es uno de los detalles que separa un diseño prolijo de uno que no.

La causa es que cada tarjeta es una grilla independiente. La tarjeta 1 no tiene idea de que el título de la tarjeta 2 ocupa dos líneas.

subgrid resuelve eso: la tarjeta deja de definir sus propias pistas y usa las del abuelo. Como todas comparten las mismas filas, todo queda alineado automáticamente.

Antes de subgrid esto se resolvía con alturas fijas o con JavaScript midiendo elementos. Ninguna de las dos era buena.

Sintaxis mínima

/* El contenedor de afuera define las pistas de verdad */
.galeria {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: auto auto auto;   /* título / desc / precio */
}

/* Cada tarjeta ocupa las 3 filas y hereda esas pistas */
.tarjeta {
  display: grid;
  grid-row: span 3;
  grid-template-rows: subgrid;
}

Las dos líneas van juntas y las dos son necesarias: span 3 dice cuántas pistas del abuelo abarca, y subgrid dice que use esas en vez de crear las suyas.

Funciona igual con grid-template-columns: subgrid, y se puede usar en un solo eje o en los dos.

Soporte: está disponible en todos los navegadores modernos (Firefox desde 2019, Safari desde 2023, Chrome y Edge desde fines de 2023). Para navegadores viejos conviene protegerlo con una feature query, que ya viste en Responsive Design: 

@supports (grid-template-rows: subgrid) {
  .tarjeta { grid-template-rows: subgrid; }
}

Resultado

Los precios están alineados. Ahora comentá grid-template-rows: subgrid y mirá cómo se desalinean: ese es exactamente el problema que resuelve.

Errores comunes

  • Olvidar el span grid-template-rows: subgrid sin grid-row: span 3 no alinea nada: la tarjeta ocupa una sola fila y no hay pistas que heredar.
  • No declarar las filas en el abuelo Si el contenedor externo no tiene grid-template-rows, no hay pistas explícitas para compartir.
  • Creer que hereda de cualquier ancestro Subgrid toma las pistas del padre inmediato que sea grid. Si hay un div intermedio sin display: grid, se corta.
  • Confundirlo con un grid anidado común Un grid dentro de otro grid siempre se pudo hacer. La diferencia es que el anidado crea pistas propias; subgrid usa las de arriba.
  • El gap también se hereda Un subgrid usa el gap del padre por defecto. Si le ponés uno propio, lo pisa, y ahí se te desalinea todo de nuevo.

Cuándo NO usarlo

✔ Usá subgrid

Cuando piezas hermanas tienen que alinearse entre sí: tarjetas de producto, formularios de etiqueta + campo, tablas de precios.

✘ Grid anidado normal

Cuando cada bloque es independiente y no necesita coordinarse con sus vecinos. Ahí subgrid solo agrega complejidad.

La pregunta que decide: ¿necesito que esta parte se alinee con la misma parte de la tarjeta de al lado? Si sí, subgrid. Si no, un grid común.

Mini-ejercicio

Un formulario de etiquetas y campos:

  1. Dos columnas: etiqueta y campo.
  2. Cada fila del formulario es un <div> propio (por el borde y el error).
  3. Que todos los campos arranquen en la misma columna, aunque las etiquetas tengan largos distintos.
Ver solución 
.formulario {
  display: grid;
  grid-template-columns: auto 1fr;
}

.fila {
  display: grid;
  grid-column: span 2;
  grid-template-columns: subgrid;
}

Sin subgrid, cada .fila calcularía su columna auto según su etiqueta, y los campos quedarían escalonados. Con subgrid, la columna auto se calcula una vez para todo el formulario: la más ancha manda.

Este caso es interesante porque acá el subgrid es de columnas, no de filas. Sirve para los dos ejes.
